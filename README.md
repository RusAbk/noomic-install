# Установщик Нумика

Публичные скрипты первой установки и обновления сервера. Исходники приложения и контейнеры остаются закрытыми: нужен аккаунт GitHub с доступом к проекту.

Ubuntu 22.04/24.04/26.04 или Debian 12/13, x86_64. Направьте домены приложения и API на сервер, откройте TCP 80 и 443. Подключитесь по SSH под root и вставьте одну команду:

```bash
bash -c 'set -eo pipefail; apt-get -o DPkg::Lock::Timeout=180 update; apt-get -o DPkg::Lock::Timeout=180 install -y ca-certificates curl; curl -fsSL https://raw.githubusercontent.com/RusAbk/noomic-install/main/install.sh | bash'
```

Загрузчик установит Docker, Compose и остальные зависимости, предложит вход GitHub по коду в браузере, затем спросит домены, email и данные первого администратора. Docker и Node.js заранее устанавливать не требуется.

Для обновления существующего сервера в `/var/noomic`:

```bash
curl -fsSL https://raw.githubusercontent.com/RusAbk/noomic-install/main/update.sh | bash -s -- apply --install-dir /var/noomic
```

Для установки в `/opt/noomic` замените путь. Используются уже установленный Docker и сохранённый вход GHCR. Сначала скачивается согласованная пара API и веба по точным digest, затем сохраняются SQL, файлы, конфигурация и прежние образы. Ссылка на текущий выпуск меняется после успешного запуска. Обновлятор не создаёт новую конфигурацию или администратора.

После успешного обновления скрипт сохраняется на сервере:

```bash
bash /var/noomic/update.sh check
bash /var/noomic/update.sh apply
bash /var/noomic/update.sh status
bash /var/noomic/update.sh rollback
```

`check` не останавливает приложение; повторное применение того же пакета не перезапускает контейнеры. Для автоматизации добавьте `--yes`, для конкретной версии — `--version sha-<полный SHA>`. Запускайте от пользователя установки, обычно root.

При сбое миграции или запуска скрипт пытается вернуть прежние контейнеры. `rollback` возвращает предыдущие образы и установочные файлы, сохраняя текущую базу и загрузки. **SQL-дамп автоматически не импортируется:** несовместимая миграция может потребовать отдельного восстановления базы. Копии находятся в `deployment/updates/<операция>/backup/`; не удаляйте их и старые образы до проверки обновления.

По умолчанию файлы находятся в `/opt/noomic`, постоянная конфигурация — в `/opt/noomic/deployment/config.env`. `bash install.sh --help` показывает параметры, включая `--yes` для автоматизации и `--release server-<полный SHA>` для выбора выпуска. Токены и пароли передавайте через защищённое окружение, не в аргументах команд.

Изменения загрузчика ведутся в `deployment/bootstrap.sh` основного репозитория. Клиент обновлений ведётся в корневом `update.sh` основного репозитория. Здесь публикуются проверенные копии без исходников приложения и секретов.
